How it works

One glasses app, one wire contract — the backend you pick is a swap, not a rewrite.

Glasses mic → phone app → your chosen backend (a direct OpenAI-compatible URL, or CI-Hub via agent-hub) → your AI (Ollama, Claude Code, Codex, OpenClaw, OpenAI, or Companion Memory) → streamed reply back to the phone and glasses HUD.

No account required to get started — bring your own backend, or connect a CI-Hub.

Open the Even Hub portal in the Even Hub mobile app and install CI Companion (package com.companionintelligence.ciglasses).

Sign in & generate your CI-Hub config

Sign in with Companion Intelligence and this page remembers your Hub and reconnects automatically next time you visit — or skip sign-in and just fill in your Hub host below. Everything runs in your browser; the only network calls are to CI-Portal (if you sign in) and to the Hub host you enter (to check it's reachable).

Every service routes through the companion agent-hub (default port 8787) — one URL for chat and voice.

Manual backend setup

For bringing your own OpenAI-compatible endpoint instead of a CI-Hub.

FieldDefault
Backend URL http://localhost:8080

API Mode auto — probes the server, or force completions / responses
Running the companion agent-hub instead (for Claude Code, Codex CLI, or OpenClaw)? Point Backend URL at its address (default port 8787) and pick the matching Backend Kind in Settings. See the agent-hub README for env vars and Docker instructions.

Supported backends

The app speaks one OpenAI-compatible wire; the Backend Kind tells it what to expect on the other end.

openai
Any OpenAI-compatible URL — OpenAI, Anthropic, Gemini, etc. Hub optional.
local-llm
Ollama / vLLM / llama.cpp on your LAN — Hermes, Llama, Qwen…
claude-cli
agent-hub spawning Claude Code — supports permission prompts, ring-approved.
codex-cli
agent-hub spawning Codex CLI — same permission-prompt flow as Claude.
openclaw
agent-hub forwarding to an OpenClaw Gateway.
memory
Recalls from Companion Memory (CI-Server) and streams the block back.

Troubleshooting

Quick answers before you file an issue.

“Running in browser mode”

The app only gets glasses-BLE features inside the Even Hub app or its simulator. Chat, settings, and AI requests still work in a plain browser — only the HUD mirror is unavailable.

No response on the HUD

The phone webview is the source of truth — if the glasses display doesn't update, check the status bar's ⚠ HUD indicator; a BLE hiccup self-clears on the next send.
